# Linkmark v1 方案（已确认：单一加密密钥库）

## 1. 目标与边界

Linkmark 是可自托管的纯静态 PWA，用于管理网站入口、基础设施连接资料和轻量密钥。静态服务器只交付构建产物，永不接触书签、入口、主密码、密钥库明文或任何解密后的数据。

v1 支持 Web、PostgreSQL、Redis 和 Generic 四类入口。它是资料管理器，不会连接、测试或管理数据库、Redis 或任何其他服务。

不在 v1 范围内：账号体系、云同步、外部系统导入导出、TOTP、附件、浏览器扩展、网页自动填充、远程 favicon/标题抓取，以及任何远程分析或 CDN 依赖。

## 2. 安全承诺与非承诺

### 承诺

- 密钥库、完整备份和分享包采用成熟密码学方案保护静态数据。
- 主密码、派生密钥和解密后的密钥库只存在于当前页面内存。
- 应用启动或刷新后必定锁定并要求输入主密码。
- 分享字符串泄露时，攻击者不能在没有分享口令的情况下读取任何入口元数据或密钥。
- 不建立任何入口或密钥的明文搜索索引；锁定时不显示名称、分组、计数、最近访问或列表。

### 不承诺

- 无法保护被 XSS 注入的正在运行页面、恶意浏览器扩展、受控浏览器配置文件或已失陷的设备。
- 无法在浏览器底层存储中提供取证级物理擦除。
- 不提供主密码找回；忘记主密码即无法恢复密钥库。
- 不提供跨设备自动同步。

应用首次创建和主密码修改页面必须明确展示这些边界，并提示用户保留加密备份。

## 3. 领域模型

| 概念 | 定义 | 持久化方式 |
| --- | --- | --- |
| 入口 | 一个保存的访问位置，包含名称、类别、分组、标签与非敏感配置。 | KDBX |
| 网站入口 | `kind = web` 的入口，可从浏览器打开。 | KDBX |
| 连接入口 | 数据库、缓存等服务的入口；只保存端点资料。 | KDBX |
| 密钥 | 加密认证资料，包含账号、密码、API Key、Token、备注和自定义字段。 | KDBX |
| 分组 | 入口的单层、互斥归属，同时定义手动排序范围。 | KDBX 应用元数据 |
| 标签 | 可附加到多个入口的交叉分类。 | KDBX 应用元数据 |
| 未关联密钥 | 没有被入口引用的密钥，等待审查或删除。 | KDBX |

一个入口可关联零到多个密钥；一个密钥也可关联多个入口。关系的唯一事实来源是入口的密钥 UUID 列表；密钥侧的关联入口为运行时反向计算结果。

### 入口最小结构

```ts
type Entry = {
  id: UUID;
  kind: 'web' | 'postgresql' | 'redis' | 'generic';
  name: string;
  groupId: UUID | null;
  tagIds: UUID[];
  sortOrder: number;
  config: Record<string, string | number | boolean>;
  keyIds: KdbxEntryUuid[];
  createdAt: ISO8601;
  updatedAt: ISO8601;
};
```

- Web：仅允许 `http:`、`https:` URL。
- PostgreSQL：host、port、database、SSL mode 等非敏感字段。
- Redis：host、port、database number、TLS 等非敏感字段。
- Generic：任意非敏感键值对，只保存、不执行。

用户名、密码、API Key、Token、含凭据的 DSN/URI 和备注均只能进入密钥，不得放入 `config`。

## 4. 本地存储与密钥库

所有业务资料只存在于一个 KDBX4 密钥库中，使用本地打包、锁版本的 `kdbxweb` 读写；不提供 KDBX 文件导入或导出。IndexedDB 只持久化该密钥库的二进制密文和无敏感的记录更新时间；`localStorage` 最多保存主题偏好。新密钥库显式选择 Argon2id，绝不使用库的默认 KDF。

Argon2id 实现采用本地、可审计且锁版本的 WASM 包，在专用 Worker 中执行。v1 使用应用固定的平衡参数：64 MiB 内存、3 次迭代、并行度 1；用户不调参。参数与算法版本写入 KDBX 和分享包。导入任何外部数据时，对包大小、KDF 内存、迭代和并行度执行严格上限校验。

KDBX 包含一个 Linkmark 专用根组及固定技术分区：“入口”“密钥”“回收站”“应用元数据”。用户可见的分组不是 KDBX 文件夹，而是入口的加密属性。KDBX 条目保存入口、密钥及其关联；锁定时不显示任何目录信息。

## 5. 解锁、锁定与删除

首次使用只能创建一个密钥库并两次输入主密码，或导入 Linkmark 加密包；没有“跳过密钥库”的浏览模式。主密码不设长度或复杂度限制，但提供本地风险提示和长口令建议；不上传或远程检测口令。

- 启动、刷新、关闭标签或浏览器重启后必锁。
- 解锁时用户选择绝对有效期：5 分钟、30 分钟、2 小时、24 小时或 7 天。
- 有效期从解锁开始计时，用户活动不会续期；到期、手动锁定或页面卸载时清除内存中的明文与派生密钥。
- 每个入口或密钥表单的“保存”都是明确保存：在 Worker 中重加密密钥库并与关联修改在 IndexedDB 原子写入。入口内新建密钥时，两者必须同时成功或均不提交。
- 密钥值默认掩码；显示与复制均由用户显式触发。应用不自动清空系统剪贴板，也不承诺能控制其他应用读取剪贴板。
- 删除的入口和密钥都进入统一回收站，30 天后自动永久清理；可手动恢复、永久删除或清空。恢复入口时仅恢复仍存在的密钥关联；删除密钥会解除所有入口关联后再进入回收站。

## 6. 导入、导出与分享

### 完整备份

唯一的常规导出格式是由当前主密码保护的完整、版本化 Linkmark JSON Package。它只封装已由 KDBX4/Argon2id 保护的密钥库密文和格式字段，故不泄露入口、分组、标签或基础设施目录；不对同一份 KDBX 密文重复执行外层 KDF。

不提供明文、仅入口、仅密钥库或外部 KDBX 的导入导出。

导入必须先预览，随后由用户选择：

- **备份恢复**：以备份主密码解锁后，原子替换本地全部数据。
- **备份合并**：同时输入备份主密码和当前主密码；解锁两侧密钥库后合并，并以当前主密码重新加密。冲突项生成新 UUID，不静默覆盖；导入副本的内部入口—密钥关系同步重写。

### 分享包

用户在解锁状态下输入独立的分享口令。应用从内存生成一份由该口令重新加密的 KDBX4 密钥库（Argon2id + KDBX 加密），再以版本化 Base64URL 信封编码并复制。KDBX 本身已是完整的认证加密容器，因此分享流程不对同一份密文重复执行第二层高成本 KDF。

分享包包头至少包含：`formatVersion`、`mode`、加密算法和 KDBX 密文。KDBX4 头部携带其盐值与 KDF 参数；导入时仍在 KDF 前执行资源上限校验。接收方粘贴字符串并输入分享口令后预览；首次导入时以接收方自己的主密码创建本机密钥库，已有密钥库时可选择替换或合并。分享口令不会成为接收方的长期主密码。

所有 Package 均具有版本字段和迁移器。遇到较新的未知版本、认证失败、字段结构非法或资源参数超限时，导入必须失败且不改写本地数据。

## 7. UI 与体验

默认简体中文，文案使用本地字典组织，为未来语言包预留边界。界面默认跟随系统深浅色，用户可手动覆盖。

- 锁定页只提供创建或导入、主密码输入和安全说明；不显示任何业务资料。解锁后才显示工作台。
- 左侧为可折叠分组导航；窄屏转为抽屉。顶部提供全局搜索、新增入口、导入导出与密钥库锁定状态。
- 主区为可切换的入口卡片/紧凑列表，首页展示置顶与最近访问。
- 入口编辑为完整表单，内含“关联已有密钥”和“新建并关联”的密钥区；独立密钥编辑复用同一份表单。服务入口仅展示和编辑资料，不提供测试、连接或 URI 生成操作。
- 搜索只在已解锁时可用，覆盖入口、分组、标签及密钥名称/账号；不建立持久化搜索索引。
- 分组单层；删除分组时其入口移入默认分组；标签可多选；每组支持持久化手动排序，名称/更新时间等排序是临时视图。
- 操作界面统一使用“入口”“密钥”“密钥库”“导入预览”等中文；仅 KDBX、Argon2id、AES-GCM 等技术标准名词保留英文。
- 核心路径（解锁、搜索、新建、保存、导入导出）支持键盘操作，满足 WCAG AA 对比度与可见焦点。

## 8. 前端与发布架构

- TypeScript + React + Vite。
- Dexie 仅管理 IndexedDB 中的密钥库密文；kdbxweb 管理 KDBX 内的全部业务资料；Zod 校验表单和不可信导入包。
- 样式使用本地构建、零运行时 CSS 方案；所有依赖锁入 lockfile 并随同源构建物发布。
- PWA 可安装、可离线启动。Service Worker 仅缓存同源构建资源，不缓存、代理或上传用户数据。
- 每次启动检查静态资源更新；有更新时提示重新加载，安全更新可以要求刷新。
- 生产部署使用 HTTPS，并配置严格 CSP；禁止第三方脚本、字体 CDN、分析 SDK、广告与自动远程 favicon/网页标题抓取。

## 9. 验收与安全测试

实现前后至少覆盖以下验证：

1. 主密码、派生密钥、密钥库明文及任何入口元数据不出现在 IndexedDB、localStorage、日志、错误上报或 Service Worker 缓存。
2. 锁定、刷新、超时、手动锁定和页面卸载后密钥库与全部业务资料均无法访问。
3. 普通备份恢复、备份合并、分享导入、错误口令、损坏包、未知版本和 KDF 超限包均符合预期，失败不改写数据。
4. 删除入口、删除分组、未关联密钥、统一回收站恢复和 30 天清理均不误删关联密钥。
5. URL 协议校验拒绝 `javascript:`、`data:`、`file:`；所有用户文本都以文本节点渲染，不使用不可信 HTML。
6. Worker KDF/加密失败、IndexedDB 空间不足、剪贴板权限拒绝、离线启动和 PWA 更新都有可理解且不泄露密钥的错误提示。
7. Chrome、Edge、Firefox、Safari 的近两年版本均验证创建、锁定、导入导出、分享和深浅色/窄屏核心流程。

## 10. 实施阶段

1. 初始化 React/TypeScript/PWA 工程、CSP 与本地依赖供应链约束。
2. 实现 KDBX 内的入口/分组/标签/密钥模型、搜索和响应式仪表盘。
3. 集成 KDBX、Argon2id Worker、创建/导入/解锁/锁定、表单级保存与入口—密钥关联。
4. 实现版本化加密备份、合并/恢复、分享包与导入安全限制。
5. 完成统一回收站、自动锁定、PWA 更新、无障碍与安全测试；开发期旧明文表不迁移也不自动清理。
